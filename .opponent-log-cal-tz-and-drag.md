- [WARN] **Click-after-drag bug.** EventBlock has both `onClick` (opens EventExpansion) AND `onPointerDown` (starts drag, owner-only). After a drag completes (pointerdown → move → up on same element), the browser fires `click` per the W3C spec. So a user who drags an owner event by 30px will see: (a) the event moves to its new slot via PATCH, (b) EventExpansion popover opens at the new location. Confusing UX. Mitigations: track `recentlyDragged` ref and short-circuit onClick if true within ~250ms, OR call `e.stopPropagation()` in pointerup. Not a BLOCKER (math is right, drag works) but B6 smoke MUST verify and B4/B5 should fix.
- [WARN] **Missing `setPointerCapture`.** Pointer-up listener is attached to `window`, but if the user's pointer leaves the browser window mid-drag, some browsers won't fire pointerup. Calling `e.currentTarget.setPointerCapture(e.pointerId)` in pointerdown forces the originating element to receive all subsequent pointer events. Reliability fix; should be added before ship.
- [WARN] **No live visual feedback.** Positiva acknowledged this in the impl comment. The user sees nothing until release, then the block jumps to the new slot. Acceptable for v1; B6 smoke must confirm the snapped result is visible enough to feel intentional.
- [WARN] B3 scope choice: positiva replaced the plan's "single integration test simulating the full pointer flow" with two narrower TDD layers (helper unit tests + DayColumn wiring tests). Decision documented in the commit body and the plan retrospective. This IS a deviation from the plan's literal text — but defensible, since pointer-flow tests in jsdom + apiFetch mocks ARE brittle and the math+wiring are both covered. **Risk**: bugs in the WeeklyGrid pointer handler (e.g., the click-after-drag above) escape unit tests entirely. B6 Chrome MCP is now load-bearing. Negativa accepts this scope choice on the condition that B6 actually exercises (a) drag a non-recurring owner event and verify it moves, (b) drag a non-owner event and verify NO move + NO PATCH fired, (c) drag a recurring event and verify the modal opens (B4-coupled).
