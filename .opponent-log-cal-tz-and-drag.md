- [WARN] **Click-after-drag bug.** EventBlock has both `onClick` (opens EventExpansion) AND `onPointerDown` (starts drag, owner-only). After a drag completes (pointerdown → move → up on same element), the browser fires `click` per the W3C spec. So a user who drags an owner event by 30px will see: (a) the event moves to its new slot via PATCH, (b) EventExpansion popover opens at the new location. Confusing UX. Mitigations: track `recentlyDragged` ref and short-circuit onClick if true within ~250ms, OR call `e.stopPropagation()` in pointerup. Not a BLOCKER (math is right, drag works) but B6 smoke MUST verify and B4/B5 should fix.

Calling `e.currentTarget.setPointerCapture(e.pointerId)` in pointerdown forces the originating element to receive all subsequent pointer events. Reliability fix; should be added before ship.
