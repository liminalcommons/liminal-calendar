# Opponent Log — Calendar stale-after-action (no live updates)

## Task
Liminal-calendar users (and the owner) have to **manually refresh** after taking actions for state to update. Cover all mutation sites:

- RSVP / un-RSVP on events
- Create / edit / delete event
- Mute / unmute event reminders
- Booking handle + slug edits, availability edits
- Profile edits
- Notification inbox: mark read, clear
- Drag-to-reschedule in week view
- Show-and-tell submissions
- Any admin/owner mutation

For each, the user action should reflect in the UI **without a manual refresh**.

## Approach (positiva, in order)
1. **Inventory** — grep for `fetch(`, server actions, mutation handlers; list every site that mutates server state. Cross-reference with the page that displays the resulting state. Produce a checklist in this file.
2. **Diagnose pattern** — likely candidates: missing `router.refresh()` after server action; missing `revalidatePath` / `revalidateTag` in route handler; client state not invalidated; SWR/React Query absent so no auto-revalidate.
3. **Fix one site end-to-end** as the reference pattern (probably RSVP since it's most visible). Browser-verify with Chrome MCP — click, confirm UI updates, no manual reload.
4. **Apply the pattern** to remaining sites in batches of 2–3, each batch browser-verified.
5. **Regression sweep** — week view, month view, list view, settings.

## Rules
- No deploy to prod until negativa confirms DONE.
- Each positiva commit must include browser screenshot evidence of dynamic update.
- No new dependencies unless absolutely necessary (prefer `router.refresh()` + `revalidatePath` over adding SWR/React Query mid-project).
- Touch only `packages/liminal-calendar/`. The calendar is a submodule — commit there, then bump the superproject pointer.

## Fix policy
- **Hooks/components that hold their own list state**: prefer optimistic update + `router.refresh()` belt-and-suspenders so server components downstream also re-render.
- **Server actions / route handlers that mutate data the landing or list pages render**: add `revalidatePath('/')` + `revalidatePath('/list')` + `revalidatePath('/month')` as appropriate. Also `revalidatePath('/[handle]', 'page')` for booking changes.
- **Drag-to-reschedule**: optimistic move + `router.refresh()` to reconcile with server truth.
- **No new deps.** Use `useRouter().refresh()` and `next/cache`.
